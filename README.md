# Broken Phone / Сломанный телефон

Настольная игра на **C# + WPF для Windows** по мотивам Dub Together, с собственным интерфейсом и режимом последовательной озвучки. Ведущий выбирает видео и способ распределения ролей. Игроки по очереди озвучивают реплики своих персонажей. Предыдущую реплику можно послушать по желанию. После последнего хода собирается общий MP4 и автоматически начинается синхронный просмотр у всех участников.

## Запуск

Актуальная версия 0.9 находится в `dist/BrokenPhone/BrokenPhone.exe`. `Run.cmd` запускает её; если сборки нет, сначала создаёт её. Путь остаётся постоянным при обновлениях. Для разработки сборка отдельно создаётся в `build/compile`.

Готовая переносимая сборка: `dist/BrokenPhone/BrokenPhone.exe`. Для передачи на другой компьютер используйте `dist/BrokenPhone-Windows-x64.zip`: распакуйте архив целиком и откройте `BrokenPhone.exe`. В архив включены пробный пак, FFmpeg и FFprobe; отдельно устанавливать их не требуется. Папки `Assets`, `tools`, а также `steam_api64.dll` и `steam_appid.txt` должны оставаться рядом с EXE. Собрать архив заново можно командой `.\package.ps1 -Verify`.

Тёмная тема включена по умолчанию. Декоративные полукруги убраны. Плитки мастерской заполняют доступную ширину; обложки имеют пропорции 16:9. Выбранный пак показывает превью, исходное число реплик и ролей; эти данные передаются гостям. Справа под настройками раунда находится полноценный «Чат» с историей сообщений. В EXE, заголовке окна и внутри игры используется общий логотип сломанной телефонной трубки.

Нужны Windows 10/11, .NET Framework 4.8 и **FFmpeg** с `ffmpeg.exe` и `ffprobe.exe`. Игра ищет инструменты в PATH, `C:\ffmpeg\bin`, рядом с EXE и в папке `tools` рядом с EXE. Отдельные NuGet-пакеты и Python не нужны. Для сборки скриптом используется компилятор из Windows .NET Framework; Unity и .NET SDK не требуются.

`BrokenPhone.csproj` можно открыть в Visual Studio с поддержкой WPF и .NET Framework 4.8. C# ограничен версией 5 для совместимости со встроенным компилятором Windows.

## Первый раунд

1. Запустите Steam и игру на обоих компьютерах. В «Подключении» выберите «Steam · без VPN», нажмите «Пригласить друзей» и отправьте приглашение из списка друзей. Также можно скопировать ссылку на комнату; друг вставляет её в «Войти в комнату». Для LAN/Radmin выберите соответствующий адрес.
2. В лобби откройте «Роли и режим». Ведущий выбирает автоматическое распределение по количеству реплик или ручной выбор. В ручном режиме каждый выбирает себе один или несколько персонажей. Затем все участники отмечают готовность. Игра рассчитана на отдельные компьютеры.
3. Нажмите «Начать озвучку». Сначала все участники подготавливают выбранный пак: недостающие видео и фон передаются ведущим и сохраняются в собственной папке `Packs`. Уже имеющиеся файлы проверяются и повторно не скачиваются. Общий экран показывает прогресс каждого; игра начинается только после проверки файлов и открытия видео у всех. Ведущий может отменить подготовку. Встроенный оригинальный пробный пак содержит четыре фрагмента по четыре секунды.
4. В свой ход можно сразу нажать «Запись». «Предыдущая» и «Оригинал» — необязательные подсказки. Исходная реплика доступна, если в паке есть оригинальный звук: дорожка видео или отдельные MP3 реплик Dub Together. Оригинальные голоса во время записи отключены. На чужом ходу отображается экран «Скоро твоя очередь» с именем говорящего и местом в очереди.
5. Во время записи отображается живая звуковая волна на всю ширину панели. Спектрограмма и частотные столбики удалены. «Мой дубль» позволяет проверить запись вместе с видео. Можно перезаписывать фрагмент и менять эффект голоса; «Дальше» отправляет обработанный дубль ведущему и передаёт ход.
6. После последней реплики ведущий автоматически монтирует все принятые голоса с видео и фоновой дорожкой. Каждый получает один и тот же готовый MP4. Когда видео загружено и подготовлено к воспроизведению у ведущего и гостей, игра назначает общий момент старта: нажимать «Смотреть» каждому не нужно. Во время подготовки виден счётчик готовности. Пауза, продолжение, перемотка и повтор ведущего применяются у всех. Каждый игрок может сохранить видео.

В «Настройках» доступны имя, выбор микрофона, проверка короткой записью до пяти секунд, громкость, скрытие кода для стрима и вход в Steam. Если устройство не открывается, игра показывает ошибку; проверьте доступ к микрофону для классических приложений в Windows.


## Выбор ролей перед раундом

Кнопка «Роли и режим» под выбранным паком открывает общий экран кастинга. Ведущий выбирает один способ для всей комнаты: «Автоматически» распределяет персонажей с учётом числа реплик; «Выбрать вручную» освобождает роли для самостоятельного выбора. В каждой карточке показаны имя персонажа, число реплик и круглая аватарка участника, занявшего роль. Карточки обновляются у всех по сети. Имена участников при подключённом Steam берутся из их профилей.

Можно взять несколько персонажей. «Снять выбор» освобождает роль: затем её может выбрать другой участник. Занятую другим игроком роль забрать нельзя. Любое изменение распределения сбрасывает готовность; начать раунд можно, когда все роли распределены и все участники подтвердили готовность. При отключении игрока его роли освобождаются; в автоматическом режиме распределяются заново. Если персонажей меньше, чем игроков, участник без роли может смотреть раунд.

Запись идёт по исходному порядку реплик, исполнитель определяется выбранной ролью. Один актёр может получить несколько ходов подряд. Пересечения таймкодов сохраняются: реплики записываются отдельно, а готовые голоса звучат одновременно в исходных местах видео. Сведение складывает дорожки и применяет ограничение громкости после смешивания, поэтому поздняя запись не стирает более раннюю. При наличии отдельных звуковых файлов «Оригинал» воспроизводит конкретную реплику своего персонажа.

Ранее подготовленные паки с объединёнными репликами восстанавливаются при чтении по сохранённым исходным INI. Если исходников в кэше нет, игра просит выбрать исходную папку пака заново. Все участники должны использовать версию 0.9 (сетевой протокол 8).

## Студия озвучки

Экран студии опирается на [скриншоты и описание Dub Together в Steam](https://store.steampowered.com/app/5020310/Dub_Together/): крупное видео в тёмной рамке, роль и текст под кадром, лента звуковой волны, эффекты и цветные округлые кнопки «Оригинал / Запись / Мой дубль / Дальше». Наш режим остаётся одной общей историей с последовательными ходами.

Для каждой реплики доступны шесть эффектов: обычный голос, бурундук, монстр, эхо, робот и телефон. Изменение высоты сохраняет длительность реплики; эхо обрезается границами отрезка. Предпросмотр, передача ведущему и финальный монтаж используют одну обработанную запись. Эффект и фильтр можно менять после записи, без повторного обращения к микрофону.

«Убирать тихий шум» — простой пороговый фильтр тихого фона между словами. Волна строится из реального сигнала и занимает всю панель; спектрограммы нет. Блок «Подсказка для сцены» удалён, в боковой панели остаётся очередь игроков. Клавиши: **R** — начать/остановить запись; **Enter** — передать готовый дубль; **Space** — прослушать свой дубль или управлять общим просмотром у ведущего; **F11 / Esc** — полноэкранное окно / выход.

Общий просмотр использует часы ведущего с поправкой на время передачи по сети. При подготовке проверяется не только наличие файла, но и открытие видео декодером. Воспроизведение корректирует заметный уход по времени; точность зависит от сети и декодера Windows. Все участники должны использовать версию 0.9.

## Проверка микрофона

В настройках выберите устройство и нажмите «Записать пробу». Записывается до пяти секунд; можно остановить раньше. Уменьшенная звуковая волна того же вида, что в студии, показывает входящий голос, прошедшее время и текущий уровень. Тихая речь отображается заметнее; тишина остаётся плоской линией. Прямого вывода микрофона в колонки во время записи нет.

После записи нажмите «Прослушать». Воспроизводится именно записанная проба, с движущимся указателем на мини-волне. Кнопка превращается в «Стоп»; запись можно слушать повторно, перезаписать или сбросить. Громкость регулируется ползунком ниже. Пустой сигнал и перегрузка отмечаются сообщением. При смене микрофона старая проба сбрасывается. При выходе из настроек запись и прослушивание останавливаются. Проба отделена от игрового дубля и удаляется при сбросе или закрытии игры.

`--microphone-ui-test` проверяет отображение входящего PCM, реальное воспроизведение WAV, повтор, остановку, выход из настроек, сброс и отображение тишины. В автотесте используется известный звук с выключенной громкостью; физический микрофон не открывается. Отчёт — `microphone-ui-test.txt`, снимок панели — `microphone-check-preview.png`.

## Игра с разных компьютеров

При выбранном LAN/Radmin «Пригласить друзей» копирует полное приглашение вида `26.12.34.56:47770/ABC123`. На другом компьютере выберите «Войти в комнату» и вставьте его. Список «Подключение» позволяет выбрать адрес Radmin VPN или локальной сети; активный Radmin-адаптер предлагается первым. Сервер принимает соединения на всех интерфейсах. По умолчанию используется TCP 47770, при занятом порте выбирается свободный. Приглашение содержит фактический адрес, порт и код. Подробные шаги — в [CONNECT.md](CONNECT.md) и в кнопке «Подключение» внутри игры.

В комнате до восьми участников, чат, готовность, удаление игроков ведущим и синхронизация состояния. При отключении участника незавершённый раунд останавливается, уже принятые записи сохраняются. При отключении ведущего гости переходят в собственную новую комнату.

Отдельная регистрация в Broken Phone не требуется. Steam-режим использует текущий профиль Steam, лобби для друзей и Steam Networking Sockets: видео, реплики и управление просмотром передаются этим каналом. Запущенный Steam определяется при старте; в настройках можно нажать «Подключить Steam». Для разработки используется **Spacewar, App ID 480**. В профиле Steam игра может отображаться как Spacewar; это тестовая интеграция. Для самостоятельного выпуска в Steam потребуется собственный App ID. В `steam_appid.txt` рядом с EXE указан используемый App ID; у участников он должен совпадать.

Приложение создаёт Steam-лобби с меткой `broken-phone` и текущим протоколом, чтобы не подключаться к другим проектам на 480. Приглашения обрабатываются в запущенной игре; перед принятием приглашения друг запускает Broken Phone 0.9. Автоматический запуск именно нашего EXE из библиотеки Steam на тестовом App ID не настроен. Публичного списка комнат нет.

Файл `Finals Week-Multiplayer-Fix-Online.exe` изучен статически: Inno Setup-установщик содержит `winmm.dll`, `SteamFix64.dll`, `SteamFix.ini` и Steam API. В конфигурации указаны `RealAppId=4715160`, `FakeAppId=480`, `Overlay=true`, `FilterLobby=false`. Это прокси для готовой Steam-интеграции другой игры. Наш код обращается к Steam API напрямую; в сборку включена подлинная библиотека `steam_api64.dll` с проверенной подписью Valve. Файлы старого исследования в выпуск не входят.

LAN/Radmin сохраняет прямое TCP-соединение с кодом комнаты. Для этого режима Steam не нужен; сеть рассчитана на игру с друзьями в общей локальной сети или VPN.

Кнопка «Вернуться в лобби» удалена. Во время записи и монтажа верхняя вкладка «Лобби» недоступна. После завершения раунда ведущий возвращает всех в лобби через верхнюю вкладку; готовность сбрасывается.

## Паки из папки (по умолчанию)

Откройте «Настройки → Паки → Папка на компьютере», нажмите «Обзор…» и сохраните настройки. В окне выбора паков также есть кнопка «Выбрать папку…»: она применяет выбор сразу. Можно выбрать папку одного распакованного пака или коллекцию с подпапками, например `SteamLibrary/steamapps/workshop/content/5020310`. Нужны уже имеющиеся файлы с `_pack_info.ini` и видео либо `pack.json`; архив сначала распакуйте. Путь запоминается. По умолчанию открывается собственная папка `Packs` и пробный пак.

Названия берутся из метаданных паков; карточки показывают обложку, число реплик и ролей. Доступны поиск по названию и фильтр языка. Пустая, недоступная папка и повреждённые паки сопровождаются сообщением. Выбранный внешний пак копируется в собственную `Packs`, OGV подготавливается в MP4; исходная папка остаётся без изменений. Перед запуском ведущий передаёт недостающие файлы участникам. Одинаковые пути на компьютерах участников не требуются.

Для чтения уже скачанных файлов вход в Steam/SteamCMD не нужен. Steam для сетевого лобби работает независимо от источника паков. При подключённом Steam имя игрока всегда берётся из его текущего профиля; сохранённый локальный псевдоним его не заменяет. Без Steam можно задать имя для LAN/Radmin в настройках.

## Steam Workshop (дополнительный источник)

Прямую загрузку из Steam можно вернуть в «Настройки → Паки → Steam Workshop». Выбор папки не меняет права на скачивание новых файлов из Steam.

Встроенная «Мастерская» обращается к **живому каталогу Dub Together, App ID 5020310**. Доступны поиск, русский/английский язык, популярные/новые паки, страницы, поиск по ID или ссылке, обложки, число реплик и ролей. Фильтр «Мои паки» показывает только коллекцию этой игры. Поддерживаются актуальные SSR-страницы Steam и прежняя HTML-разметка.

В мастерской можно заранее скачать один пак либо отметить несколько и нажать «Скачать выбранные». Одновременно работают две задачи; обращения к одному загрузчику SteamCMD выполняются по очереди. Карточки показывают прогресс, состояние очереди и подготовки, отмену и ошибки. Кнопка загрузки недоступна, пока пак загружается, повторные клики не создают дубликаты. Загруженный пак выбирается в лобби отдельным нажатием; предзагрузка не меняет текущий выбор и не закрывает мастерскую. При выборе обложка и исходные счётчики сразу передаются всем.

Проценты и МБ показываются, когда сервер или SteamCMD сообщает объём. На этапах без измеримого процента (подготовка, SteamCMD без счётчика) отображаются название этапа и индикатор ожидания. Глобальная кнопка отменяет текущую задачу, на карточке — конкретный пак, «Отменить все» — всю очередь.

Кнопка «Загрузить» работает так:

1. В режиме Steam Workshop уже скачанный этой игрой пак выбирается из собственной папки `Packs/ID`. В режиме «Папка на компьютере» читаются паки из выбранной пользователем папки.
2. Для нового пака запрашиваются данные официального Steam API. Если API выдаёт прямую HTTPS-ссылку, файл скачивается с неё. Иначе автоматически устанавливается официальный SteamCMD в `.runtime/SteamCMD` рядом с этой игрой и вызывается `workshop_download_item 5020310 ID validate`.
3. Загрузчик хранит исходные файлы в собственном каталоге этой игры, затем видео и метаданные подготавливаются в `Packs/ID`. Для получения новых паков не требуется выбирать папку оригинальной игры.
4. Если Steam требует авторизацию: «Настройки → Паки → Steam Workshop → Аккаунт Steam» → укажите имя входа → «Войти в Steam». Пароль и код Steam Guard вводятся только в открывшемся официальном окне загрузчика. После успешного входа введите `quit`, вернитесь в игру и повторите загрузку. Вход сохраняется загрузчиком для следующих запусков.

При проверке реального пака `3803788232` сервер Steam отклонил анонимное скачивание. Полная загрузка требует входа в аккаунт с необходимым доступом; проверка авторизованного скачивания без пользовательского входа не выполнялась. В интерфейсе показывается ошибка Steam вместо попытки забрать файлы из другой установленной игры. Журнал доступен в `.runtime/steamcmd.log`.

Во время загрузки доступна кнопка **«Отменить»** в общей панели, которая остаётся видимой при переходе между страницами. Отмена прерывает запрос метаданных, передачу файла, официальный загрузчик вместе с дочерними процессами, копирование и преобразование видео. Частичный HTTP-файл и временная папка импорта удаляются. Пак не подменяет уже выбранный в лобби. Steam может сохранять свои промежуточные данные внутри `.runtime/SteamCMD` для следующей попытки.

Поддерживается **реальный формат установленных паков Dub Together**: `_pack_info.ini`, `dub_video.ogv`, `_backing_track.ogg` и INI-файлы реплик с `caption`, `dub_timestamps`, `dub_ends`, `dub_characters`. При импорте видео преобразуется в H.264 MP4, а оригинальный фон используется при финальном сведении. Реплики разных персонажей и пересекающиеся таймкоды сохраняются отдельно. Одна длинная исходная реплика при необходимости делится на части до 60 секунд с сохранением персонажа.

Для проверки исходного формата используется в том числе Workshop-пак `3800178075`, «Журнал Шкипера (DAITE DENEG)»: 38 исходных реплик и 6 ролей. Старые версии объединяли в нём пересечения; текущая версия сохраняет отдельные реплики и персонажей. Будущие версии формата могут потребовать обновления адаптера.

Steam API предоставляет метаданные, но у проверенного пака не даёт публичную ссылку на содержимое. Скачивание новых паков требует Steam/SteamCMD; совместимость с установленным форматом не означает доступ к любым файлам без аккаунта и соответствующих разрешений Steam.

После старта пак передаётся участникам комнаты автоматически: каждому гостю не требуется отдельно проходить Workshop. Проверяются контрольные суммы видео и фона, сохраняются обложка, исходные числа реплик и ролей. Пока хотя бы один участник не подтвердил готовность пакета и декодера, запись недоступна. Поддерживаются пакеты до 2 ГБ; передача одного файла ограничена десятью минутами.

## Свои паки

«Импортировать» принимает собственное видео, ZIP, `.dubpack` с ZIP-структурой либо `pack.json` из папки пака. Импортированные материалы тоже сохраняются в собственной папке `Packs`. Для Workshop используется кнопка «Загрузить» на карточке Steam. Пример своего JSON-пака:

```json
{
  "title": "Наша сцена",
  "description": "Короткий диалог",
  "language": "Russian",
  "video": "video.mp4",
  "background": "background.wav",
  "lines": [
    { "start": 0, "end": 4, "text": "Начни историю", "role": "Первый" },
    { "start": 4, "end": 8, "text": "Ответь предыдущему", "role": "Второй" }
  ]
}
```

`background` необязателен. В итоговом видео используются записанные голоса и, при наличии, эта фоновая дорожка; исходный звук видео не включается. Разделение исходной речи и музыки с помощью ИИ не реализовано.

Таймкоды — в секундах; пересечения разрешены, до 60 секунд на реплику и до 500 реплик. Поле `role` определяет персонажа и его исполнителя. Адаптер также распознаёт распространённые имена полей `segments`, `dialogue`, `start_time`, `end_time`, `start_ms`, `end_ms`, `subtitle`, `character` и относительные пути `res://`. Если метаданных нет, видео делится на равные отрезки примерно по четыре секунды, о чём сообщается в лобби. Это автоматическая нарезка, а не распознавание оригинальных реплик.

Видео предпочтительно MP4 H.264. Возможность открыть другие контейнеры внутри WPF зависит от установленных декодеров Windows.

## Данные и проверка

Подготовленные паки хранятся в `Packs` рядом с EXE. В локальном режиме «Открыть папку ↗» открывает выбранный источник; в режиме Steam «Мои паки ↗» открывает собственную папку игры. Настройки, загрузчик Steam, кэш и записи хранятся в `.runtime`. Сессии с принятыми дублями остаются в `.runtime/sessions`. Папка сохранения по умолчанию — `exports` рядом с EXE. Не удаляйте папку сессии, если нужны исходные записи.

Сборка и интеграционные проверки:

```powershell
.\build.ps1 -Test
```

Проверки создают две настоящие TCP-сессии, при наличии Radmin подключают клиента через его реальный адаптер, проверяют запрет локальных игроков, полномочия ведущего, готовность, порядок ходов, статус записи для ожидающих, передачу видео и реплик, сведение MP4 со звуком в каждом отрезке, необязательное прослушивание и возврат в лобби. Проверяются все шесть эффектов, сохранение длительности, фактическая высота голоса, фильтр тихого шума, волну реального PCM и отображение тишины, исходные аудиофрагменты, одинаковый финальный MP4 у двух клиентов и общий старт после готовности ведущего и гостей. Дополнительно проверяются иконка собранного EXE, отмена реальной HTTP-передачи с очисткой частичного файла, остановка FFmpeg и дочерних процессов загрузчика. Запись настоящего микрофона в тестах не включается. Сценарий двух разных физических компьютеров требует проверки на стороне пользователей.

Дополнительные проверки собранной игры:

```powershell
.\build\compile\BrokenPhone.exe --steam-test
.\build\compile\BrokenPhone.exe --steam-ui-test
.\build\compile\BrokenPhone.exe --workshop-test
.\build\compile\BrokenPhone.exe --ui-smoke
.\build\compile\BrokenPhone.exe --input-ui-test
.\build\compile\BrokenPhone.exe --pack-downloads-ui-test
.\build\compile\BrokenPhone.exe --microphone-ui-test
.\build\compile\BrokenPhone.exe --screening-test
.\build\compile\BrokenPhone.exe --screenshot
.\build\compile\BrokenPhone.exe --design-test
```

Результаты появляются в `build/workshop-test.txt`, `build/ui-smoke.txt`, `build/self-test.txt`; изображения — `build/lobby-preview.png` и `build/round-preview.png`. Проверка Workshop требует подключения к интернету. UI-проверка проходит путь от лобби до открытия реального видео и доступной кнопки записи, без включения микрофона. Сценарий `--screening-test` открывает два настоящих игровых окна, проходит все ходы без прослушивания, проверяет автопоказ финального видео, общую паузу, перемотку, продолжение, повтор и завершение на последнем кадре. Отчёт — `build/screening-test.txt`, снимки — `studio-waveform-preview.png`, `screening-host-preview.png` и `screening-guest-preview.png`. Дополнительно `--pack-test ПУТЬ_К_ПАКУ` проверяет импорт и сведение настоящего установленного пака; отчёт — `build/native-pack-test.txt`.

Steam-проверки требуют запущенного Steam с вошедшим профилем. `--steam-test` создаёт настоящее Steam-лобби и передаёт полный раунд через Steam Networking Sockets с подключением к собственному профилю для теста. `--steam-ui-test` проводит тот же путь в двух игровых окнах, включая общий автопоказ. Отчёты — `steam-test.txt` и `steam-screening-test.txt`. Приглашения реальным друзьям тесты не отправляют. Проверка с двумя разными Steam-профилями на разных физических ПК остаётся необходимой для проверки внешнего маршрута. Для проверки переносимой сборки с обоими сетевыми режимами: `.\package.ps1 -Verify -VerifySteam`.

Исходники: `src/SteamBridge.cs`, `src/SteamNative.cs` и `src/SteamTunnel.cs` — лобби и транспорт Steam; `src/Network.cs` — сервер и клиент; `src/Packs.cs` — импорт; `src/Workshop.cs` — Steam; `src/Audio.cs` — микрофон и сведение; `src/Voice.cs` и `src/SignalView.cs` — эффекты и визуализация звука; `src/Studio.cs` — запись и синхронный просмотр; `src/Playback.cs` — общая временная шкала; `src/App.cs` — интерфейс и игровой цикл; `UI/MainWindow.xaml` — визуальное оформление.

Оригинальные изображения интерфейса и пробный клип созданы для этого проекта. Материалы и код Dub Together не включены.

Источники интеграции: [Steam Workshop Dub Together](https://steamcommunity.com/workshop/browse/?appid=5020310), [официальный API GetPublishedFileDetails](https://partner.steamgames.com/doc/webapi/ISteamRemoteStorage#GetPublishedFileDetails), [документация Steam UGC](https://partner.steamgames.com/doc/api/ISteamUGC).

Steam API: [обзор SDK](https://partner.steamgames.com/doc/sdk/api), [Spacewar](https://partner.steamgames.com/doc/sdk/api/example), [лобби и приглашения](https://partner.steamgames.com/doc/api/ISteamMatchmaking), [Steam Networking Sockets](https://partner.steamgames.com/doc/api/ISteamNetworkingSockets).

Вход в Steam и мастерская — разные уровни доступа. Сетевой режим работает в контексте Spacewar (480), а паки относятся к Dub Together (5020310). Это не выдаёт лицензию и разрешения на его Workshop. Публичный каталог и общедоступные ссылки читаются без входа; при загрузке через SteamCMD нужен его сохранённый вход в аккаунт с необходимым доступом. Вход в клиент Steam не заменяет вход в отдельный SteamCMD. Гости получают пак от ведущего и отдельно авторизовываться в загрузчике не должны.

Поля ввода используют единый исправленный шаблон: внутренние отступы применяются один раз. `--input-ui-test` проверяет видимость кириллицы и каретки в чате, поиске и настройках. `--pack-downloads-ui-test` проверяет пакетный выбор, блокировку кнопок, прогресс, отмену и мгновенную передачу обложки/счётчиков гостю. Сетевые проверки дополнены обязательной общей подготовкой паков и защитой от повреждённых файлов.

Результаты проверок последнего выпуска и снимки интерфейса находятся в `build/qa`. Найденная коллекция прежних запусков перенесена в `dist/BrokenPhone/Packs`; записи и прежние настройки сохранены в `UserData/previous-recordings-settings.zip`. Старые исполняемые сборки и архивы удаляются скриптом `tools/CleanReleases.ps1 -Clean`; запущенные старые копии пропускаются.

Проверки ролей: `--role-lines-test` проверяет отдельные пересекающиеся реплики, импорт и восстановление старых паков; `--role-mix-test` декодирует готовый MP4 и проверяет наличие обоих голосов в пересечении и отдельный оригинал; `--roles-network-test` проверяет реальные сетевые назначения, перевыбор, запреты и монтаж; `--roles-ui-test` проверяет два игровых окна с круглыми аватарками, количеством реплик, перевыбором и стартом по выбранным ролям.
