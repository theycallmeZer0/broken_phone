# Прямая загрузка паков Workshop в Broken Phone

Проверено 7 ноября 2026 года. Исследование дополнено реализованным решением и результатом настоящей локальной загрузки. Ограничение пользователя соблюдено: используется уже вошедший клиент Steam, без отдельного входа SteamCMD/DepotDownloader; приглашения открываются через Steam Overlay, когда он доступен.

## Реализованное решение и результат

В `src/SteamWorkshop.cs` используется публичный native `ISteamUGC` через уже вошедший клиент Steam. Сначала запрос выполняется из существующего `SteamBridge` основной игры, AppID `480`. При отказе доступа запускается копия собственного EXE как изолированный помощник в контексте AppID `5020310`; он присоединяется к тому же клиенту и профилю Steam без нового логина. Полученный Steam-кэш импортируется в собственную `BrokenPhone/Packs`. Выбирать папку установленной Dub Together не требуется. Каталог продолжает работать через общедоступный Web API.

Реальная проверка `build/compile/BrokenPhone.exe --steam-workshop-test 3808612351` завершилась успешно. В `build/compile/steam-workshop-test.txt` зафиксированы подключение к текущему Steam-клиенту в основном контексте `480` и импорт пака: **43 реплики, 3 роли**. При отдельной диагностике прямой запрос из `480` был отклонён callback с AppID `480` и кодом `42`; успешный путь использовал помощника `5020310`. Это подтверждает работу на проверенном компьютере и профиле, а не универсальную возможность загрузки чужого Workshop из AppID `480`.

## Что уже реализовано

В `src/Workshop.cs` сохранены каталог, получение подробностей через `GetPublishedFileDetails` и HTTPS-загрузка при наличии `file_url`. Если прямой ссылки нет, вызывается `ClientDownload`, связанный с `SteamBridge.DownloadWorkshopItem`. SteamCMD, его установка и отдельная авторизация удалены из действующего загрузчика и интерфейса. DepotDownloader не используется.

Помощник создаётся в `.runtime/cache/workshop-client`: копируются наш EXE и уже используемая `steam_api64.dll`, записывается локальный `steam_appid.txt` со значением `5020310`. Только внутри дочернего процесса устанавливаются `SteamAppId` и `SteamGameId` в `5020310`. Основной процесс сохраняет AppID `480` и собственное лобби. Файлы Steam credential/session не читаются и токены не переносятся. Текущая игра остаётся на .NET Framework 4.8 и C# 5 (`BrokenPhone.csproj`).

Перед запуском помощника проверяется `BIsSubscribedApp(5020310)`: текущему Steam-профилю нужен доступ к Dub Together. В обоих native-контекстах ожидается реальный результат callback `3406`, а затем `GetItemInstallInfo`; проверяются запрошенный ID, AppID и код результата. Путь к установленной Dub Together вручную не подставляется. Прогресс поступает из Steam, а импорт использует существующий `PackLibrary.Import`.

## Что подтверждают локальные логи

В `dist/BrokenPhone-0.13/.runtime/SteamCMD/logs/workshop_log.txt` сохранились отказы 30 октября 2026 года:

- Для AppID `5020310` зарегистрировано `Workshop depot not defined, legacy support only`.
- Для пака `3804583942` зарегистрировано `No workshop depot defined, skipping non-legacy item`, затем `Failure`.
- Для пака `3808612351` зарегистрирован отказ инициализации depot `5020310` с `Missing decryption key`.

Последний отказ подтверждается `content_log.txt`, а `console_log.txt` содержит общие сообщения об ошибке загрузки обоих ID. Это наблюдения прежних запусков, не результат новой загрузки. По этим строкам нельзя определить, каким аккаунтом выполнялась попытка, была ли у него лицензия, а также изменились ли разрешения на стороне Steam с той даты. Данные аккаунтов и сессий не исследовались и не переносились.

## Свежая проверка публичного API

На исследовательском этапе 7 ноября выполнен POST к [официальному API метаданных](https://partner.steamgames.com/doc/webapi/ISteamRemoteStorage#GetPublishedFileDetails), без входа и без скачивания содержимого самим этим запросом:

- `3804583942`: `result=1`, `consumer_app_id=5020310`, размер `79702069` байт, `hcontent_file=8969055434013340137`; `file_url` отсутствует или пуст.
- `3808612351`: `result=1`, `consumer_app_id=5020310`, размер `14918666` байт, `hcontent_file=5082485983518695569`; `file_url` отсутствует или пуст.

Следовательно, эти два пака видимы через публичный API, но получить из этого ответа прямую HTTPS-ссылку для существующей ветки скачивания нельзя. Видимость описания и обложки сама по себе не подтверждает доступность содержимого. Ответ с `hcontent_file` подходит к сценарию manifest/CDN; такое разделение есть в [реальной реализации DepotDownloader](https://github.com/SteamRE/DepotDownloader/blob/master/DepotDownloader/ContentDownloader.cs).

Не требует встраивания своей игры в Steam. В исходниках ветка Workshop выбирает `file_url` либо `hcontent_file`; дальнейшая загрузка проверяет права аккаунта, определяет workshop depot и запрашивает ключ. Отдельный код аутентификации поддерживает современные Steam-сессии. Источники: [параметры](https://github.com/SteamRE/DepotDownloader/blob/master/README.md), [загрузка](https://github.com/SteamRE/DepotDownloader/blob/master/DepotDownloader/ContentDownloader.cs), [Steam-сессия](https://github.com/SteamRE/DepotDownloader/blob/master/DepotDownloader/Steam3Session.cs).

**WorkshopDL++.** Внешний менеджер Workshop со встроенным каталогом и очередью. Текущий официальный репозиторий прямо сообщает, что часть загрузок требует аккаунта, владеющего игрой, и загружает SteamCMD с серверов Valve. Значит, такой интерфейс возможен, но замена на WorkshopDL сама по себе не исправляет отказ SteamCMD. У проекта лицензия CC BY-NC-SA 4.0; копировать его код как универсальную библиотеку для игры не следует. Источник: [официальный репозиторий noitavo/workshopdl](https://github.com/noitavo/workshopdl). Одноимённые сторонние сайты не использовались как доказательство работоспособности.

**RimSort.** Открытый внешний менеджер RimWorld; его исходник действительно формирует `login anonymous` и `workshop_download_item 294100`, записывая содержимое в собственный каталог SteamCMD. Это хороший образец очереди, отмены и импорта для игры, купленной вне Steam. Однако он работает с разрешениями Workshop конкретной RimWorld; их нельзя переносить на AppID Dub Together. Источники: [репозиторий](https://github.com/RimSort/RimSort), [обёртка SteamCMD](https://github.com/RimSort/RimSort/blob/main/app/utils/steam/steamcmd/wrapper.py). RimPy найден как аналог, но для доказательств механизма выбран доступный исходник RimSort.

## Ограничения Steam и AppID

`DownloadItem` принимает ID пака и приоритет, без целевого AppID. Возврат `true` означает начало запроса; перед использованием файлов нужно дождаться `DownloadItemResult_t`, проверить `m_unAppID`, `m_nPublishedFileId`, `m_eResult`, затем вызвать `GetItemInstallInfo`. Callback приходит всем запущенным приложениям, поэтому чужой callback сам по себе не подтверждает возможность cross-app загрузки. Описанный временный кэш для неподписанных пользователей не обещает анонимный доступ ко всем Workshop. `BInitWorkshopForGameServer` предназначен только для game server; документация прямо указывает `false`, если вызывающий не game server. Его нельзя использовать для смены каталога/контекста обычного клиента AppID `480`. Источник: [ISteamUGC](https://partner.steamgames.com/doc/api/ISteamUGC).

Steam API инициализируется в контексте AppID, а наличие лицензии активного пользователя — одно из официально указанных условий инициализации. Отсюда вывод: успешное подключение Spacewar для лобби не доказывает права на depot Dub Together. Простая смена `steam_appid.txt` не является законченным решением загрузки и может изменить контекст существующего сетевого режима. Источник: [Steamworks API Overview](https://partner.steamgames.com/doc/sdk/api#SteamAPI_Init).

Если вошедшему пользователю API отказывает в cross-app загрузке, публичного гарантированного обхода этого ограничения для нашего AppID в исследованных источниках не найдено. Наличие и состояние настройки anonymous-download у AppID `5020310` не подтверждено. Публикация Broken Phone в Steam с собственным AppID сама по себе не открывает чужой Workshop.

Реализованный помощник подтвердил техническую возможность присоединения к текущему Steam-пользователю в контексте `5020310` без нового логина. Это локально проверенный режим совместимости, а не согласованная с владельцем чужого AppID публичная Steamworks-интеграция: Valve описывает `steam_appid.txt` как средство разработки и просит не поставлять его с релизом. Для публичного распространения такой контекст требует отдельного решения с владельцем AppID/Valve. Установка игры не названа обязательным условием самой инициализации, но локальный тест не доказывает поведение чистого компьютера без её установки. Основной процесс не меняет AppID и не перезапускает Steam API во время лобби `480`. Источники: [SteamAPI_Init](https://partner.steamgames.com/doc/sdk/api#SteamAPI_Init), [steam_api.h](https://partner.steamgames.com/doc/api/steam_api#SteamAPI_Init).

## Схема работы и оставшиеся проверки

1. Каталог и сведения пака → HTTPS при наличии `file_url`, иначе native-запрос текущего SteamBridge `480`.
2. При отказе доступа → проверка прав текущего профиля на `5020310` → изолированный собственный помощник с этим AppID и той же Steam-сессией.
3. Callback `3406` с правильным ID/AppID и `EResult.OK` → `GetItemInstallInfo` → `PackLibrary.Import` → наша `Packs/<id>`.
4. Отмена прекращает ожидание, останавливает собственного помощника и отменяет наш импорт. У Steam API нет отдельной отмены одного native Workshop-запроса, поэтому Steam может продолжить свою фоновую загрузку; глобальное `SuspendDownloads` не используется.
5. Подтверждён реальный импорт `3808612351`. Ещё нужны проверки другого пака, обновления, отказа доступа, потери сети, отмены и чистого компьютера с другим разрешённым профилем. Эти результаты не следует приписывать уже пройденному тесту.
6. Ведущий выбирает карточку Workshop до скачивания файлов. Выбор с отдельным токеном сразу передаётся всем участникам, затем начинается поиск локальной копии и разрешённая прямая загрузка. Пока файлов нет, готовность и старт недоступны. Участник с копией предлагает её ведущему; тот получает файлы через проверяемую передачу между игроками и публикует полный выбранный пак. Запоздалые предложения и завершения предыдущей загрузки игнорируются.

## Загрузка без Dub Together на аккаунте

Для передачи имеющихся файлов между участниками лицензия Dub Together не проверяется. Готовая копия может находиться у гостя, даже если ведущий не может скачать её через Steam. Предложение привязано к текущему выбору и Workshop ID; адрес источника задаёт сервер комнаты, а описание, части и итоговые файлы проверяются по SHA-256. После получения копии ведущим работает общая раздача.

Начальное получение копии от гостя использует канал Steam между участниками либо доступный сетевой порт гостя. Если прямой маршрут недоступен, план частей и сами части передаются через уже установленное соединение комнаты. Запросы разрешены только ведущему, для предложенного текущего пака и зарегистрированного источника; личные записи в эту передачу не входят. Контрольные суммы проверяются и в резервном канале. Отключение гостя сразу завершает ожидание с ошибкой, а отмена удаляет частичные файлы.

Для полного описания пака действует строгий порядок: проверенная локальная копия, затем Steam, при его отказе или несовпадении версии — раздача частей участниками, затем резервный канал комнаты. Steam и раздача больше не соревнуются параллельно. Публикация полного описания ведущим не отменяет уже идущую Steam-загрузку у гостя.

Это не создаёт отсутствующие файлы и не меняет разрешения Steam. Публичная прямая ссылка используется при наличии `file_url`; если её нет, ни у кого нет копии и клиент Steam не разрешает скачивание, комната остаётся в ожидании источника. В частности, публичные сведения пака `3803458272` доступны, но проверенный ответ API содержит пустой `file_url`. Поддержка анонимного `DownloadItem` для игровых серверов в [документации Valve](https://partner.steamgames.com/doc/api/isteamugc#DownloadItem) сама по себе не подтверждает доступность такой загрузки для Dub Together.

Проверки `--workshop-selection-test`, `--workshop-peer-test` и `--workshop-selection-ui-test` используют локальные сетевые сессии: выбор до загрузки, передача гостем ведущему без Steam, проверка файлов, отмена и смена выбора. Это не проверка двух физических компьютеров или анонимного доступа к серверам Steam.

## Steam Overlay и приглашения

В `Program.Launch` основной `SteamBridge` теперь создаётся до `new Application()` и загрузки WPF Window, затем передаётся контроллеру через `StartupSteam`. Это соответствует требованию Valve инициализировать Steam до создания D3D/OpenGL device. Overlay поддерживает DirectX 7–12, но не программный рендеринг. Источник: [Steam Overlay](https://partner.steamgames.com/doc/features/overlay).

При доступном overlay `InviteFriends()` теперь вызывает `ActivateGameOverlayInviteDialog(LobbyId)`: Steam показывает приглашения в переданное лобби. При недоступном overlay сохранён существующий список друзей и копирование кода комнаты. Callback `GameLobbyJoinRequested_t` принимается в `SteamBridge.Dispatch`. Источник: [ISteamFriends](https://partner.steamgames.com/doc/api/ISteamFriends#ActivateGameOverlayInviteDialog).

Shift+Tab по умолчанию обрабатывает сам Steam Overlay; пользователь может сменить сочетание в Steam. Копировать только это сочетание в WPF как единственный способ открытия не следует. Доступность проверяется через `IsOverlayEnabled`, который сначала может быть `false`, пока Steam устанавливает hook. Открытие должно проверяться в реальном игровом окне; вызов API с возвратом `void` ещё не подтверждает видимость. Источник: [Steam Overlay](https://partner.steamgames.com/doc/features/overlay).

WPF перерисовывает окно по событиям, тогда как overlay нуждается в `Present`. Valve рекомендует примерно 33 раза в секунду проверять `BOverlayNeedsPresent` и обеспечивать новый кадр. В коде добавлен таймер 30 мс, меняющий непрозрачность небольшой WPF-поверхности при запросе Steam. Это реализованная поддержка перерисовки; сам тест Workshop не доказывает видимость overlay и работу ввода поверх WPF на всех компьютерах. Источник: [ISteamUtils](https://partner.steamgames.com/doc/api/ISteamUtils#BOverlayNeedsPresent).

Рассмотренный ранее вариант отдельной авторизации DepotDownloader/SteamKit исключён из актуального решения. Для сравнения: на момент исследования `master` [DepotDownloader.csproj](https://github.com/SteamRE/DepotDownloader/blob/master/DepotDownloader/DepotDownloader.csproj) уже указывает `net10.0`; [SteamKit](https://github.com/SteamRE/SteamKit/blob/master/readme.md) также требует .NET 10. Старое упоминание .NET 8 в README DepotDownloader не следует принимать за совместимость исходников. DepotDownloader распространяется под [GPL-2.0](https://github.com/SteamRE/DepotDownloader/blob/master/LICENSE). Native Steam API уже используется нашей .NET Framework 4.8 игрой и отдельного современного .NET runtime не требует.

Если требуется полностью независимый от лицензии Dub Together каталог, отдельный продуктовый путь — собственное хранилище паков, которые авторы разрешили распространять. Это снимает зависимость от разрешений чужого Workshop, но требует своего источника контента, версий и проверки файлов. Массовое копирование чужой мастерской не предлагается.

## Граница подтверждённого результата

Подтверждены код реализации, прежние SteamCMD-ошибки, публичные метаданные двух паков, отказ прямого native-запроса из `480` и успешная загрузка/импорт `3808612351` через собственный помощник `5020310` с текущим Steam-профилем. Повторная авторизация не выполнялась; credential/session файлы не читались. Основной процесс остался `480`. Отчёт `build/compile/steam-workshop-test.txt` подтверждает 43 реплики и 3 роли. Чистый компьютер без установленной Dub Together, другой аккаунт, другие паки, а также полноценная публичная поставка с чужим AppID этим тестом не подтверждены. Проверки overlay нужно оценивать отдельно от успешной загрузки Workshop.
